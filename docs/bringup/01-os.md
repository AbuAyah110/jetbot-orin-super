### Swap: reconcile the spec, do not recreate the swap

The board's swap is already correct in every way that matters — 32 GiB, on the NVMe, active, and in `fstab`. Only the *path* and *swappiness* differ from `JETBOT_SPEC.md`.

Do **not** run `scripts/setup_swap.sh` to move it to `/swapfile`. That script would allocate a second 32 GiB file, append another `fstab` entry, and rewrite `vm.swappiness` — a boot-integrity risk and 32 GiB of wasted NVMe for zero functional gain.

Instead, treat `/ssd/32GB.swap` with `vm.swappiness=60` as the sanctioned configuration and update the spec and the setup scripts to match. Evidence that the current setting is not hurting anything: the F4 ASR gate peaked at 466 MiB RSS with system `MemAvailable` never below 3.9 GiB and **0 MB of the 32 GiB swap touched** (see [06-voice.md](06-voice.md)). Revisit swappiness only if a measured workload shows the kernel swapping while RAM is still free.
